Create a complete 2D incompressible Navier–Stokes airfoil solver in Python 3.13 using a conformal Joukowski-type mapping, a vorticity–streamfunction formulation, SciPy multithreaded FFTs, NumPy, and PySide6.

The purpose is to solve viscous unsteady flow around an airfoil on a body-fitted spectral grid obtained by conformally mapping a simple circular computational domain into an airfoil-shaped physical domain.

The solver must visibly reproduce:
- circulation around the airfoil,
- stagnation regions,
- boundary-layer development,
- wake formation,
- vorticity generation at the airfoil surface,
- separated flow when the angle of attack / Reynolds number is high enough,
- vortex shedding when appropriate,
- and a physically meaningful pressure coefficient Cp distribution.

The airfoil geometry must NOT be represented by a Cartesian mask or Brinkman penalization.
The airfoil surface must be an exact coordinate boundary of the transformed computational domain.

============================================================
PHYSICAL PROBLEM
============================================================

Solve the 2D incompressible Navier–Stokes equations around an airfoil.

Use a vorticity–streamfunction formulation.

Physical coordinates:

    z = x + i y

Velocity:

    u = dpsi/dy
    v = -dpsi/dx

Vorticity:

    omega = dv/dx - du/dy

Governing equations:

    d omega / dt + J(psi, omega) = nu * Laplacian(omega)

    Laplacian(psi) = -omega

where

    J(psi, omega)
      = dpsi/dx * domega/dy
      - dpsi/dy * domega/dx

No pressure projection should be required for time integration.

Recover pressure afterward for visualization and Cp calculation.

Use:

    Re = U_inf * c / nu

with default:

    U_inf = 1.0
    chord = 1.0
    Re = 1000
    alpha = 5 degrees

and therefore:

    nu = U_inf * chord / Re

Support GUI-editable values for at least:

    Re
    alpha
    U_inf
    Nr
    Ntheta
    CFL
    outer-domain radius
    visualization field
    frame skip

============================================================
CONFORMAL AIRFOIL MAPPING
============================================================

Use a Joukowski-type conformal mapping.

Begin with a circle in the auxiliary complex plane:

    zeta = xi + i eta

The basic Joukowski transform is:

    z = zeta + a^2 / zeta

but do NOT restrict the implementation to a centered circle if that only creates a symmetric flat-plate-like geometry.

Use an offset circle:

    zeta(theta) = zeta_c + R * exp(i theta)

and choose zeta_c and R such that the mapped contour forms a proper finite-thickness cambered or symmetric airfoil.

The implementation must expose a clean AirfoilMapping class.

It should provide functions equivalent to:

    zeta(s, theta)
    z(s, theta)
    dz_dzeta(zeta)
    metric(s, theta)
    surface_xy()
    computational_to_physical(...)
    velocity_computational_to_physical(...)

Normalize the resulting airfoil so that:

    leading edge x approximately 0
    trailing edge x approximately 1
    chord approximately 1

The angle of attack must be implemented through the free-stream orientation, not by rotating the numerical grid unnecessarily.

============================================================
COMPUTATIONAL COORDINATES
============================================================

Use polar coordinates around the generating circle.

Represent the auxiliary-domain radial coordinate as:

    zeta = zeta_c + r * exp(i theta)

Use a logarithmic radial coordinate:

    s = ln(r / R)

so that:

    s = 0

corresponds exactly to the airfoil surface.

The computational domain becomes:

    0 <= s <= s_max
    0 <= theta < 2*pi

where theta is periodic.

The physical outer radius should be sufficiently large to approximate free stream.

Default outer-domain radius should be approximately:

    10 to 20 chord lengths

or an equivalent value in the auxiliary plane chosen consistently with the mapping.

============================================================
METRIC
============================================================

For the conformal map:

    z = f(zeta)

define:

    h = |df/dzeta|

With logarithmic radial coordinate, define the combined metric factor H:

    H = r * |df/dzeta|

so that:

    Laplacian_z(phi)
      = (1/H^2) * (phi_ss + phi_thetatheta)

Derive and implement all metric factors carefully.

Do NOT approximate derivatives of the mapping numerically if closed-form expressions are available.

For the Joukowski transform:

    f(zeta) = zeta + a^2/zeta

    f'(zeta) = 1 - a^2/zeta^2

Use analytical expressions.

Store metric arrays as contiguous NumPy arrays.

Validate that metric values are finite throughout the numerical domain except where an exact Joukowski cusp would cause a singularity.

============================================================
TRAILING EDGE
============================================================

The exact Joukowski cusp can make:

    f'(zeta) -> 0

at the trailing edge.

Do NOT allow an unresolved singular metric to destroy the solver.

Implement one numerically robust strategy.

Preferred strategy:

Use a slightly regularized Joukowski/Kármán–Trefftz-like configuration that produces a very thin but finite trailing-edge angle rather than an exact mathematical cusp.

If using the pure Joukowski transform, regularize the metric in a mathematically controlled way and clearly document it.

The implementation must contain tests ensuring:

    no NaN metric values
    no Inf metric values
    no catastrophic timestep collapse at the trailing edge

Do not simply clip arbitrary large values without documenting and justifying the numerical treatment.

============================================================
SPECTRAL DISCRETIZATION
============================================================

Use a hybrid spectral method.

Theta direction:
    Fourier spectral

Radial/log-radius direction:
    Chebyshev collocation

Recommended default:

    Ntheta = 512
    Nr = 160

Support smaller test configurations such as:

    Ntheta = 128
    Nr = 64

and larger configurations such as:

    Ntheta = 1024
    Nr = 256

Theta derivatives must use FFT.

For a field f(s, theta):

    f_theta
    f_thetatheta

must be computed spectrally with scipy.fft.

Use Fourier wavenumbers generated consistently with a 2*pi-periodic domain.

Radial derivatives:

    f_s
    f_ss

must use Chebyshev differentiation matrices or an equivalent stable Chebyshev spectral operator.

Avoid constructing unnecessary dense operations inside every timestep.

Precompute:

    Chebyshev nodes
    first derivative matrix
    second derivative matrix
    theta wavenumbers
    dealiasing mask
    mapping coordinates
    metric arrays
    surface geometry

============================================================
CHEBYSHEV GRID
============================================================

Use Chebyshev–Gauss–Lobatto nodes.

Map:

    x_cheb in [-1, 1]

to:

    s in [0, s_max]

Ensure:

    s = 0

is exactly the airfoil wall.

Use the node clustering near the airfoil to resolve the viscous boundary layer.

Be careful with node ordering.

Make sure all operators consistently use the same wall-to-farfield ordering.

============================================================
VORTICITY–STREAMFUNCTION EQUATIONS
============================================================

Using the conformal metric H:

    psi_ss + psi_thetatheta = -H^2 * omega

and

    d omega/dt
      + (1/H^2) *
        (psi_s * omega_theta - psi_theta * omega_s)
      =
        nu/H^2 *
        (omega_ss + omega_thetatheta)

Implement this formulation explicitly.

Verify signs carefully against the definitions:

    u = psi_y
    v = -psi_x

    omega = dv/dx - du/dy

Do not silently change conventions between modules.

============================================================
STREAMFUNCTION POISSON SOLVER
============================================================

At every required stage, solve:

    psi_ss + psi_thetatheta
      = -H^2 * omega

Exploit the Fourier direction.

Transform RHS in theta using scipy.fft.

For each Fourier mode k:

    psi_hat_ss - k^2 * psi_hat
      = rhs_hat

Solve the resulting 1D Chebyshev boundary-value problem.

Precompute one radial linear operator/factorization per unique |k| where practical.

Use:

    scipy.linalg

for LU factorization / solve if appropriate.

Do not invert matrices explicitly.

The streamfunction solve should be one of the most optimized parts of the implementation.

============================================================
FAR-FIELD CONDITIONS
============================================================

Impose uniform free-stream flow at angle alpha.

Physical free-stream velocity:

    Ux = U_inf * cos(alpha)
    Uy = U_inf * sin(alpha)

The far-field streamfunction in Cartesian coordinates is:

    psi_inf = Ux * y - Uy * x

up to an arbitrary constant.

Evaluate this on the mapped outer boundary and impose it as the outer Dirichlet condition for psi.

At the wall, streamfunction must be constant because the wall is impermeable.

Set:

    psi_wall = constant

Choose the constant consistently.

Allow circulation to develop dynamically due to the no-slip viscous boundary rather than prescribing an inviscid Kutta circulation directly.

============================================================
NO-SLIP WALL CONDITION
============================================================

This is critical.

The airfoil surface is:

    s = 0

Impose:

    u = 0
    v = 0

at the wall.

In streamfunction form:

    psi = constant

provides no penetration, but no-slip additionally requires the correct wall vorticity.

Implement a stable wall-vorticity boundary condition based on the streamfunction near the wall.

Use a high-order spectral/generalized Thom-type relation compatible with the Chebyshev discretization.

Do NOT simply set:

    omega_wall = 0

because that is physically incorrect.

The implementation must clearly isolate this logic in a function such as:

    update_wall_vorticity(...)

Test that wall tangential velocity approaches zero to numerical accuracy.

============================================================
OUTER VORTICITY CONDITION
============================================================

At the far field:

    omega = 0

or use a consistent weak/open outer condition.

For the default large outer radius, zero far-field vorticity is acceptable.

Add an optional damping layer near the outer boundary if needed to absorb outward-moving vortical disturbances.

If a sponge is implemented, it must operate only near the far boundary and not contaminate the airfoil flow.

============================================================
NONLINEAR TERM
============================================================

Compute:

    N =
      (1/H^2) *
      (psi_s * omega_theta - psi_theta * omega_s)

using pseudo-spectral evaluation.

Use 2/3 dealiasing in the periodic theta direction.

At minimum:

    transform nonlinear quantity to Fourier space
    zero modes above 2/3 cutoff
    transform back

Prefer dealiasing of participating derivative/product fields consistently.

Avoid aliasing-driven instability.

============================================================
TIME INTEGRATION
============================================================

Use a robust low-storage third-order Runge–Kutta method.

Preferred:

    SSPRK3

or a documented low-storage RK3.

Treat the nonlinear advection explicitly.

For moderate Reynolds number, explicit viscous integration may be acceptable at smaller grids, but the default production solver should avoid a timestep dominated unnecessarily by Chebyshev wall clustering.

Preferred production method:

    IMEX RK3

or

    integrating-factor / semi-implicit viscous treatment

where the stiff radial diffusion contribution is treated implicitly if reasonably implementable.

If implementing fully explicit RK3 initially, compute and enforce both:

    advective CFL condition
    diffusive stability condition

and choose:

    dt = safety * min(dt_adv, dt_diff)

The application must remain stable for its documented default case.

============================================================
CFL
============================================================

Compute a physically meaningful local timestep using mapped-grid cell scales.

Approximate local coordinate cell lengths with the metric:

    dx_s approximately H * ds
    dx_theta approximately H * dtheta

Then constrain:

    dt_adv approximately CFL *
      min(
        dx_s / |u_s|,
        dx_theta / |u_theta|
      )

or an equivalent correct formulation using contravariant coordinate velocities.

Also include viscous stability if diffusion is explicit.

Default:

    CFL = 0.4

Display:

    current dt
    CFL estimate

in the GUI.

============================================================
VELOCITY RECOVERY
============================================================

Recover computational coordinate velocity components from psi.

For conformal coordinates with equal scale factor H:

    q_s      = (1/H) * psi_theta
    q_theta  = -(1/H) * psi_s

subject to the chosen sign convention.

Then rotate/transform these components into physical Cartesian:

    u(x,y)
    v(x,y)

using the analytical coordinate basis vectors from the conformal mapping.

Implement this transformation carefully and test it against a known uniform-flow streamfunction.

============================================================
PRESSURE
============================================================

Pressure is not needed to advance the vorticity equation, but it is needed for Cp.

Recover pressure periodically, not necessarily every timestep.

Use the incompressible pressure Poisson equation:

    Laplacian(p)
      =
      -rho *
      [
        (du/dx)^2
        + 2*(du/dy)*(dv/dx)
        + (dv/dy)^2
      ]

or an equivalent divergence-of-momentum formulation.

Solve this in transformed coordinates.

Use:

    rho = 1

unless exposed otherwise.

Set a far-field pressure reference:

    p_inf = 0

Pressure recovery may be computed only every visualization frame to reduce cost.
