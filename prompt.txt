Create a complete 2D incompressible Navier–Stokes airfoil solver in Python 3.13 using a conformal Joukowski-type mapping, a vorticity–streamfunction formulation, a mandatory SciPy/NumPy float64 reference backend, a persistent MLX backend on supported Apple Silicon, and PySide6.

The purpose is to solve viscous unsteady flow around an airfoil on a body-fitted spectral grid obtained by conformally mapping a simple circular computational domain into an airfoil-shaped physical domain.

The solver must visibly reproduce:
- circulation around the airfoil,
- stagnation regions,
- boundary-layer development,
- wake formation,
- vorticity generation at the airfoil surface,
- separated flow when the angle of attack / Reynolds number is high enough,
- vortex shedding when appropriate,
- and a physically meaningful pressure coefficient Cp distribution.

The airfoil geometry must NOT be represented by a Cartesian mask or Brinkman penalization.
The airfoil surface must be an exact coordinate boundary of the transformed computational domain.

============================================================
PHYSICAL PROBLEM
============================================================

Solve the 2D incompressible Navier–Stokes equations around an airfoil.

Use a vorticity–streamfunction formulation.

Physical coordinates:

    z = x + i y

Velocity:

    u = dpsi/dy
    v = -dpsi/dx

Vorticity:

    omega = dv/dx - du/dy

Governing equations:

    d omega / dt + J(psi, omega) = nu * Laplacian(omega)

    Laplacian(psi) = -omega

where

    J(psi, omega)
      = dpsi/dx * domega/dy
      - dpsi/dy * domega/dx

No pressure projection should be required for time integration.

Recover pressure afterward for visualization and Cp calculation.

Use:

    Re = U_inf * c / nu

with default:

    U_inf = 1.0
    chord = 1.0
    Re = 1000
    alpha = 5 degrees

and therefore:

    nu = U_inf * chord / Re

Support GUI-editable values for at least:

    Re
    alpha
    U_inf
    Nr
    Ntheta
    CFL
    outer-domain radius
    visualization field
    frame skip

============================================================
CONFORMAL AIRFOIL MAPPING
============================================================

Use a Joukowski-type conformal mapping.

Begin with a circle in the auxiliary complex plane:

    zeta = xi + i eta

The basic Joukowski transform is:

    z = zeta + a^2 / zeta

but do NOT restrict the implementation to a centered circle if that only creates a symmetric flat-plate-like geometry.

Use an offset circle:

    zeta(theta) = zeta_c + R * exp(i theta)

and choose zeta_c and R such that the mapped contour forms a proper finite-thickness cambered or symmetric airfoil.

The implementation must expose a clean AirfoilMapping class.

It should provide functions equivalent to:

    zeta(s, theta)
    z(s, theta)
    dz_dzeta(zeta)
    metric(s, theta)
    surface_xy()
    computational_to_physical(...)
    velocity_computational_to_physical(...)

Normalize the resulting airfoil so that:

    leading edge x approximately 0
    trailing edge x approximately 1
    chord approximately 1

The angle of attack must be implemented through the free-stream orientation, not by rotating the numerical grid unnecessarily.

============================================================
COMPUTATIONAL COORDINATES
============================================================

Use polar coordinates around the generating circle.

Represent the auxiliary-domain radial coordinate as:

    zeta = zeta_c + r * exp(i theta)

Use a logarithmic radial coordinate:

    s = ln(r / R)

so that:

    s = 0

corresponds exactly to the airfoil surface.

The computational domain becomes:

    0 <= s <= s_max
    0 <= theta < 2*pi

where theta is periodic.

The physical outer radius should be sufficiently large to approximate free stream.

Default outer-domain radius should be approximately:

    10 to 20 chord lengths

or an equivalent value in the auxiliary plane chosen consistently with the mapping.

============================================================
METRIC
============================================================

For the conformal map:

    z = f(zeta)

define:

    h = |df/dzeta|

With logarithmic radial coordinate, define the combined metric factor H:

    H = r * |df/dzeta|

so that:

    Laplacian_z(phi)
      = (1/H^2) * (phi_ss + phi_thetatheta)

Derive and implement all metric factors carefully.

Do NOT approximate derivatives of the mapping numerically if closed-form expressions are available.

For the Joukowski transform:

    f(zeta) = zeta + a^2/zeta

    f'(zeta) = 1 - a^2/zeta^2

Use analytical expressions.

Store metric arrays as contiguous NumPy arrays.

Validate that metric values are finite throughout the numerical domain except where an exact Joukowski cusp would cause a singularity.

============================================================
TRAILING EDGE
============================================================

The exact Joukowski cusp can make:

    f'(zeta) -> 0

at the trailing edge.

Do NOT allow an unresolved singular metric to destroy the solver.

Implement one numerically robust strategy.

Preferred strategy:

Use a slightly regularized Joukowski/Kármán–Trefftz-like configuration that produces a very thin but finite trailing-edge angle rather than an exact mathematical cusp.

If using the pure Joukowski transform, regularize the metric in a mathematically controlled way and clearly document it.

The implementation must contain tests ensuring:

    no NaN metric values
    no Inf metric values
    no catastrophic timestep collapse at the trailing edge

Do not simply clip arbitrary large values without documenting and justifying the numerical treatment.

============================================================
SPECTRAL DISCRETIZATION
============================================================

Use a hybrid spectral method.

Theta direction:
    Fourier spectral

Radial/log-radius direction:
    Chebyshev collocation

Recommended default:

    Ntheta = 512
    Nr = 160

Support smaller test configurations such as:

    Ntheta = 128
    Nr = 64

and larger configurations such as:

    Ntheta = 1024
    Nr = 256

Theta derivatives must use the active backend's FFT implementation.

For a field f(s, theta):

    f_theta
    f_thetatheta

must be computed spectrally with ``scipy.fft`` in the float64 reference and
with ``mlx.core.fft`` while remaining device-resident in the MLX backend.

Use Fourier wavenumbers generated consistently with a 2*pi-periodic domain.

Radial derivatives:

    f_s
    f_ss

must use Chebyshev differentiation matrices or an equivalent stable Chebyshev spectral operator.

Avoid constructing unnecessary dense operations inside every timestep.

Precompute:

    Chebyshev nodes
    first derivative matrix
    second derivative matrix
    theta wavenumbers
    Fourier and radial dealiasing/filter data
    mapping coordinates
    metric arrays
    surface geometry

============================================================
CHEBYSHEV GRID
============================================================

Use Chebyshev–Gauss–Lobatto nodes.

Map:

    x_cheb in [-1, 1]

to:

    s in [0, s_max]

Ensure:

    s = 0

is exactly the airfoil wall.

Use the node clustering near the airfoil to resolve the viscous boundary layer.

Be careful with node ordering.

Make sure all operators consistently use the same wall-to-farfield ordering.

============================================================
VORTICITY–STREAMFUNCTION EQUATIONS
============================================================

Using the conformal metric H:

    psi_ss + psi_thetatheta = -H^2 * omega

and

    d omega/dt
      + (1/H^2) *
        (psi_s * omega_theta - psi_theta * omega_s)
      =
        nu/H^2 *
        (omega_ss + omega_thetatheta)

Implement this formulation explicitly.

Verify signs carefully against the definitions:

    u = psi_y
    v = -psi_x

    omega = dv/dx - du/dy

Do not silently change conventions between modules.

============================================================
STREAMFUNCTION POISSON SOLVER
============================================================

At every required stage, solve:

    psi_ss + psi_thetatheta
      = -H^2 * omega

Exploit the Fourier direction.

Transform RHS in theta using the active backend FFT.  Use ``scipy.fft`` with
float64 arrays for the reference implementation.  In MLX, keep the transformed
RHS, modal solve, and inverse transform on device; do not cross to SciPy between
the forward and inverse transforms.

For each Fourier mode k:

    psi_hat_ss - k^2 * psi_hat
      = rhs_hat

Solve the resulting 1D Chebyshev boundary-value problem.

Precompute one radial linear operator/factorization per unique |k| where practical.

Use:

    scipy.linalg

for LU factorization / solve if appropriate.

Do not invert matrices explicitly.

The streamfunction solve should be one of the most optimized parts of the implementation.

============================================================
FAR-FIELD CONDITIONS
============================================================

Impose uniform free-stream flow at angle alpha.

Physical free-stream velocity:

    Ux = U_inf * cos(alpha)
    Uy = U_inf * sin(alpha)

The far-field streamfunction in Cartesian coordinates is:

    psi_inf = Ux * y - Uy * x

up to an arbitrary constant.

Evaluate this on the mapped outer boundary and impose it as the outer Dirichlet condition for psi.

At the wall, streamfunction must be constant because the wall is impermeable.

Set:

    psi_wall = constant

Choose the constant consistently.

Allow circulation to develop dynamically due to the no-slip viscous boundary rather than prescribing an inviscid Kutta circulation directly.

============================================================
NO-SLIP WALL CONDITION
============================================================

This is critical.

The airfoil surface is:

    s = 0

Impose:

    u = 0
    v = 0

at the wall.

In streamfunction form:

    psi = constant

provides no penetration, but no-slip additionally requires the correct wall vorticity.

Implement a stable wall-vorticity boundary condition based on the streamfunction near the wall.

Use a high-order spectral/generalized Thom-type relation compatible with the Chebyshev discretization.

Do NOT simply set:

    omega_wall = 0

because that is physically incorrect.

The implementation must clearly isolate this logic in a function such as:

    update_wall_vorticity(...)

Test that wall tangential velocity approaches zero to numerical accuracy.

============================================================
OUTER VORTICITY CONDITION
============================================================

At the far field:

    omega = 0

or use a consistent weak/open outer condition.

For the default large outer radius, zero far-field vorticity is acceptable.

Add an optional damping layer near the outer boundary if needed to absorb outward-moving vortical disturbances.

If a sponge is implemented, it must operate only near the far boundary and not contaminate the airfoil flow.

============================================================
NONLINEAR TERM
============================================================

Compute:

    N =
      (1/H^2) *
      (psi_s * omega_theta - psi_theta * omega_s)

using pseudo-spectral evaluation.

Use 2/3 dealiasing in the periodic theta direction.

At minimum:

    transform nonlinear quantity to Fourier space
    zero modes above 2/3 cutoff
    transform back

Prefer dealiasing of participating derivative/product fields consistently.

Avoid aliasing-driven instability.

Also control aliasing in the Chebyshev/log-radius direction.  Prefer a true
3/2-padded Chebyshev product evaluation using DCT-I coefficient conventions,
or an equivalent backend-native padded Chebyshev transform.  A carefully
documented smooth high-mode filter applied only to the nonlinear term is an
acceptable fallback if padded products are not yet practical.

Do NOT apply a blanket radial filter or hard truncation to ``omega``, ``psi``,
the viscous operator, wall-vorticity values, or complete Runge–Kutta stage
states.  The physical wall layer has genuine high Chebyshev content; filtering
the state can corrupt boundary values, smear the layer across the domain, or
create new global ringing.  Radial filtering must not be used merely to hide
concentric artifacts in the renderer.  Test its modal action and its boundary
impact explicitly.

For MLX, implement radial padding/filtering with persistent device-resident
arrays, an FFT-based DCT-I equivalent, or precomputed device operators.  Do not
round-trip through SciPy DCT inside a timestep.

============================================================
TIME INTEGRATION
============================================================

Use the three-stage low-storage semi-implicit method ``LS_IMEX_RK3`` for the
production timestepper.  Use the coefficients from the supplied
``turbo_simulator.py`` reference:

    alpha = (8/15, 5/12, 3/4)
    beta  = (0, -17/60, -5/12)

The cumulative stage output times for time-dependent boundary/startup data are:

    c = (8/15, 2/3, 1)

Use these stage times consistently rather than applying the completed-step
boundary value to all three stages.

For an equation written as:

    omega_t = L(omega) + N(omega)

where ``L`` is the treated-implicitly viscous operator and ``N`` contains the
explicit nonlinear and other nonstiff terms, each low-storage stage must be
implemented consistently with:

    (I - alpha_i * dt * L) omega_i
      =
    (I + beta_i * dt * L) omega_previous
      + alpha_i * dt * N_current
      + beta_i  * dt * N_previous

Update the stored previous nonlinear term exactly once per stage, as in the
local reference.  Document the sign convention used for ``L`` and verify the
scheme on scalar decay and manufactured diffusion problems.

Accuracy warning: the supplied recurrence has the third-order explicit RK
stability polynomial, but with nonzero ``L`` it is only first-order accurate
for pure implicit scalar decay.  Retain the ``LS_IMEX_RK3`` name only as the
reference implementation's identifier; do not describe the complete split
method as third-order.  Measure and report the explicit and implicit orders.  A
genuinely third-order full IMEX method requires a different, documented tableau
and must not be substituted silently for the supplied recurrence.

At minimum, treat the stiff mapped radial diffusion:

    L_r(omega) = nu/H^2 * omega_ss

implicitly.  Treating the full mapped viscous operator implicitly is also
acceptable if its coupled solve is correct and efficient.  Incorporate wall
and outer vorticity conditions consistently into every implicit stage solve.
Precompute or cache stage operators/factorizations when the timestep policy
allows it, and use batched/device-resident solves in MLX.

The production timestep must no longer be pinned to approximately 3e-9 by the
explicit Chebyshev wall spacing at the documented ``Nr=160`` default.  The
adaptive constraint should be based primarily on mapped advective CFL and any
remaining explicitly treated terms.  Keep a fully explicit float64 stepper
only as a small-grid reference/testing option; it must not be the default GUI
path.

The application must remain stable and advance meaningful physical time for
its documented default case.  A large timestep count while displayed physical
time remains effectively zero is a failed production configuration, not an
acceptable performance tradeoff.

============================================================
CFL
============================================================

Compute a physically meaningful local timestep using mapped-grid cell scales.

Approximate local coordinate cell lengths with the metric:

    dx_s approximately H * ds
    dx_theta approximately H * dtheta

Then constrain:

    dt_adv approximately CFL *
      min(
        dx_s / |u_s|,
        dx_theta / |u_theta|
      )

or an equivalent correct formulation using contravariant coordinate velocities.

Also include viscous stability if diffusion is explicit.

Default:

    CFL = 0.4

Display:

    current dt
    CFL estimate

in the GUI.

============================================================
VELOCITY RECOVERY
============================================================

Recover computational coordinate velocity components from psi.

For conformal coordinates with equal scale factor H:

    q_s      = (1/H) * psi_theta
    q_theta  = -(1/H) * psi_s

subject to the chosen sign convention.

Then rotate/transform these components into physical Cartesian:

    u(x,y)
    v(x,y)

using the analytical coordinate basis vectors from the conformal mapping.

Implement this transformation carefully and test it against a known uniform-flow streamfunction.

============================================================
PRESSURE
============================================================

Pressure is not needed to advance the vorticity equation, but it is needed for Cp.

Recover pressure periodically, not necessarily every timestep.

Use the incompressible pressure Poisson equation:

    Laplacian(p)
      =
      -rho *
      [
        (du/dx)^2
        + 2*(du/dy)*(dv/dx)
        + (dv/dy)^2
      ]

or an equivalent divergence-of-momentum formulation.

Solve this in transformed coordinates.

Use:

    rho = 1

unless exposed otherwise.

Set a far-field pressure reference:

    p_inf = 0

Pressure recovery may be computed only every visualization frame to reduce cost.

    lower surface

============================================================
INITIAL CONDITION
============================================================

Initialize from uniform free-stream flow around the mapped body.

Preferred:

Construct an inviscid potential-flow streamfunction around the generating circle at the selected angle of attack, transformed into the physical domain.

Alternatively, start from a smooth ramped free-stream field satisfying wall impermeability.

Another acceptable path is a deterministic full-strength initial state whose
``psi``, ``omega``, wall/far-field data, and no-slip condition satisfy the
discrete Poisson and boundary equations to measured tolerances.  For example,
add a smooth radial lift to the harmonic slip flow and reconstruct compatible
vorticity.  A verified compatible full-strength state does not require a ramp.

Do not initialize an arbitrary discontinuity at the no-slip wall.

Ramp the no-slip/free-stream forcing over a short startup interval if necessary to suppress an unphysical impulsive vorticity spike.

If a startup ramp is used, it must be a smooth function of physical simulation time and
must be evaluated consistently at the LS-IMEX-RK3 stage times.  Do NOT force
the ramp to completion after a fixed number of steps and do not use a
``max(time/startup_time, step_count/N)`` shortcut.  With a stiff explicit
timestep, that shortcut turns a nominally smooth startup into an almost
instantaneous impulse, generates an unresolved wall layer, and excites global
radial Chebyshev oscillations.

Any startup compatibility iterations must operate on a nonzero, physically
meaningful ramp state; iterations performed while all boundary targets are
zero do not seed a boundary layer.  Verify that startup produces bounded wall
vorticity, decreasing wall slip, no domain-wide alternating radial tail, and
monotone advancement of physical time.

The initial condition must be deterministic.

    fuse/batch operations where practical
    realize the lazy graph at bounded stage or completed-step checkpoints
    synchronize before recording benchmark timings
    transfer one selected field at most per rendered GUI frame

Do not advertise FFT-only offload as GPU acceleration.  Do not place a SciPy
LU solve between an MLX forward FFT and MLX inverse FFT.  Do not repeatedly
cast float64 NumPy state to float32 MLX and back inside the timestep.

The SciPy float64 backend is the correctness oracle.  The MLX float32 backend
must show convergent agreement in fields and diagnostics at appropriately
documented tolerances.  It must also beat SciPy in synchronized, warm,
end-to-end steps per second by a statistically meaningful margin before
``auto`` selects it or the GUI labels it accelerated.  Compare identical
grids, physics, pressure cadence, and diagnostic cadence; report both results.

============================================================
NUMERICAL DIAGNOSTICS
============================================================

Continuously check for:

    NaN
    Inf
    exploding max vorticity
    negative/invalid dt
    severe wall-slip error

Fail gracefully.

Do not silently continue a numerically corrupted simulation.

============================================================
TESTS
============================================================

Create a comprehensive pytest suite.

At minimum include tests for:

1. Joukowski geometry
   - finite mapped coordinates
   - chord normalization
   - closed airfoil contour

2. Metric
   - finite
   - positive away from allowed regularized trailing edge
   - stable trailing-edge behavior

3. Fourier derivative
   For:
       f(theta) = sin(k theta)
   verify:
       df/dtheta = k cos(k theta)

4. Fourier second derivative

5. Chebyshev derivative
   Verify using low-order polynomials.

6. Laplacian transformation
   Test a smooth known function.

7. Streamfunction Poisson solver
   Use a manufactured solution.

8. Uniform-flow velocity recovery
   Verify physical u,v against known free stream away from the body.

9. Incompressibility
   Verify numerical divergence is small.

10. Wall impermeability

11. Wall no-slip
   Verify tangential wall velocity is small after boundary update.

12. Far-field velocity
   Verify it approaches U_inf at alpha.

13. Dealiasing
   Verify modes above cutoff are removed.

14. Deterministic initialization

15. Finite values after multiple timesteps

16. Positive finite timestep

17. Viscous decay
   With advection disabled or appropriate manufactured state.

18. Pressure Poisson manufactured solution

19. Cp finite values

20. Headless short simulation
   Run approximately 10–50 timesteps on a small grid.

21. Physical wake sanity test
   For an angle-of-attack case, verify nonzero downstream vorticity develops.

22. Symmetry sanity test
   For alpha = 0 and symmetric geometry at early times,
   verify approximate upper/lower symmetry.

23. Circulation sign
   For positive alpha after startup,
   verify circulation has the conventionally expected sign according to the implementation's documented convention.

24. LS_IMEX_RK3 coefficients and observed order
   Verify the exact ``alpha`` and ``beta`` tuples above and scalar linear decay.
   Demonstrate third-order convergence for the purely explicit recurrence and
   explicitly characterize the supplied recurrence's first-order pure-implicit
   convergence.  Do not assert third-order convergence for the complete split
   method unless a different order-consistent tableau is implemented and named.

25. Implicit radial diffusion
   Verify unconditional decay of stiff radial modes over timesteps that exceed
   the explicit Chebyshev diffusion limit, with wall and outer boundary values
   enforced at every stage.

26. Compatible initialization or physical-time startup ramp
   Always verify the discrete initialization compatibility residuals and the
   absence of an impulsive vorticity spike.  If a ramp is used, also verify that
   its value depends on physical/stage time rather than step count and that two
   histories reaching the same time obtain the same boundary target.

27. Radial alias control
   Verify low Chebyshev modes are preserved, rejected/padded modes behave as
   documented, the radial axis is correct, and nonlinear dealiasing does not
   overwrite wall or outer state values.

28. Radial ringing regression
   On a moderate mapped grid, verify startup vorticity is localized near the
   wall/wake rather than forming an alternating-sign tail across nearly every
   radial node.  Use a quantitative modal/tail measure, not image comparison.

29. SciPy/MLX backend comparison
   Always test the SciPy float64 reference.  When MLX and a Metal device are
   available, compare mapping-independent operators, Poisson/implicit stage
   residuals, several complete steps, circulation, energy, and wall slip using
   justified float32 tolerances.  Skip cleanly when MLX is unavailable.

30. Backend gating and cumulative FPS
   Test that failed correctness or benchmark gates force ``auto`` to SciPy.
   Test cumulative FPS with an injected monotonic clock, including paused-time
   inclusion, reset behavior, and integer display formatting.

============================================================
PHYSICS VALIDATION
============================================================

The solver does not need to reproduce a particular experimental dataset exactly.

However, verify qualitatively that:

At alpha = 0:
    approximately symmetric flow for symmetric geometry.

At small positive alpha:
    upper/lower pressure asymmetry appears.
    circulation becomes nonzero.
    positive lift develops according to the chosen sign convention.

At higher alpha and/or Re:
    separated vorticity develops downstream.
    wake becomes unsteady.

Avoid claiming quantitative high-Re turbulence accuracy.

This is a 2D laminar/unsteady spectral Navier–Stokes solver.

============================================================
IMPORTANT DESIGN CONSTRAINT
============================================================

Do NOT revert to:

    Cartesian FFT
    +
    immersed boundary
    +
    Brinkman penalization

The central purpose of this project is to investigate whether a body-fitted conformally mapped spectral Navier–Stokes formulation can provide superior resolution around an airfoil.

The airfoil boundary must remain a coordinate surface.
